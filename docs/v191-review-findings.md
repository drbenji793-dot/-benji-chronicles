# Reader v191: evidence based editorial findings

Starting point: live v190, main commit 63790be1f69ada2a39c347af4937c96479918e54. Its source tree matches the local v190 working base.

Review previously saved whole reports only. The shared Review page now also stores individual findings with stable IDs, exact saved chapter quotes and paragraph references, issue, reader impact, suggested repair, evidence type, severity, confidence and review origin. Existing reports and manuscript bodies are retained. Paragraph numbering is shown by Open saved passage and is based on text blocks in that saved HTML.

Creating a finding loads only the selected chapter body and checks its revision and quotation. It captures chapter identity/revision, planning revision/content fingerprint, language and saved book rules. Missing rules versions are labelled unavailable rather than invented. Duplicate evidence/issue entries are rejected.

Each finding can be accepted for a separate proposal, rejected, deferred or sent for clarification with a recorded reason. Decisions check chapter and planning sources and reject stale sources. These states never authorize manuscript edits, mark a repair applied or claim verification. Findings and their parent are stamped through the shared write mechanism. Draft findings and decision notes stay on the device if saving conflicts. Updates use book, branch and expected revision filters.

Cards are collapsed by default, with compact stacked controls. A readable UTF-8 HTML findings export preserves quotes and source stamps in one bottom Technical details panel, with persistent Download HTML and Open file links. Same-assistant self critique is explicitly labelled as not independent validation.

## Deliberate limits

There is no automatic AI service or claim that a model has reviewed the story. This implements attributed editorial entry and decision tracking. Structured external report import, automated name/continuity checks, linked before/after manuscript proposals, author approval of prose, repair application and verified resolution remain separate outstanding tracker criteria. Existing reports without planning stamps are not retroactively given invented provenance. Actual iPhone Safari acceptance is not established by automated or desktop checks.

## Verification

The new regression exercises Arabic and English entry, exact quote matching, empty text, duplicate rejection, stale planning/chapter refusal, cross-book isolation, per-record stamps, preserved source records, recovered drafts on conflict and safe HTML export. The complete release suite and edition builds are run before publication. No production content writes are performed for testing.
